# glim

Rust로 작성 중인 2D 게임 엔진. 상용 엔진을 대체하려는 목적이 아니라,
게임 엔진의 구조를 밑바닥부터 이해하기 위해 직접 만들어보는 학습 프로젝트다.

`wgpu` 위에서 동작하며 Vulkan / DX12 / Metal / OpenGL 백엔드를 지원한다.

## 현재 상태

초기 개발 단계. 창을 띄우고 화면을 지우는 것까지 동작한다.

- [x] 창 생성 및 이벤트 루프 (winit)
- [x] wgpu 초기화 — 어댑터, 디바이스, 서피스 설정
- [x] 리사이즈 및 서피스 상태 복구 처리
- [ ] 렌더 파이프라인, 셰이더, 삼각형 그리기
- [ ] 텍스처 로딩과 스프라이트 렌더링
- [ ] 스프라이트 배치 렌더러 (인스턴싱)
- [ ] 입력 추상화, 고정 타임스텝 루프
- [ ] 리소스 매니저 (핸들 기반)
- [ ] 엔티티 구조
- [ ] AABB 충돌, 타일맵
- [ ] 오디오, 텍스트, UI

## 요구 사항

- Rust (stable, MSVC 툴체인)
- Windows: Visual Studio Build Tools — **"C++를 사용한 데스크톱 개발"** 워크로드 필수.
  이게 없으면 `linker 'link.exe' not found`로 빌드가 실패한다.
- Vulkan 또는 DX12를 지원하는 GPU

## 실행

```bash
cargo run -p glim-app
```

로그를 보려면:

```bash
# PowerShell
$env:RUST_LOG="info"; cargo run -p glim-app

# bash
RUST_LOG=info cargo run -p glim-app
```

어두운 남색 창이 뜨고 콘솔에 선택된 GPU 정보가 출력되면 정상이다.

## 구조

```
glim/
├── crates/
│   ├── glim/          엔진 라이브러리
│   │   └── src/
│   │       ├── lib.rs
│   │       └── render.rs    wgpu 초기화 및 프레임 렌더링
│   └── glim-app/      데모 애플리케이션 (엔진의 첫 번째 사용자)
└── assets/
```

엔진과 애플리케이션을 별도 크레이트로 분리했다. 크레이트 경계가 의존 방향을
컴파일 타임에 강제하므로, 엔진이 특정 게임의 사정을 알게 되는 오염을 막을 수 있다.
현재 `glim-app`은 `wgpu`를 직접 참조하지 않으며, 이 상태를 유지하는 것이 목표다.

## 설계 노트

**렌더 파이프라인은 미리 정의한다.** OpenGL처럼 상태를 그때그때 바꾸는 대신,
셰이더와 블렌딩, 정점 레이아웃을 하나의 파이프라인 객체로 굳혀두고 바인딩만 한다.
초기 보일러플레이트는 늘어나지만 상태 누수 버그가 사라진다.

**소유권은 인덱스로 표현한다.** 부모/자식 포인터로 씬 그래프를 만들면 보로우
체커와 충돌하고, `Rc<RefCell<>>`로 우회하면 나중에 전부 갈아엎게 된다.
제너레이셔널 아레나에 인덱스로 참조하는 방식을 기본으로 한다.

**추상화는 두 번째 구현이 생겼을 때 한다.** 백엔드가 하나뿐인데 트레잇을
만들지 않는다.

## 알려진 이슈

- Windows에서 Vulkan 백엔드 사용 시 `windows_read_data_files_in_registry` 경고가
  출력된다. Vulkan 로더가 선택적 디버그 레이어를 찾지 못해 남기는 메시지이며
  동작에는 영향이 없다.
- `wgpu`는 메이저 버전마다 API가 자주 바뀐다. 컴파일 에러가 "필드가 없다 /
  타입이 다르다"로 나온다면 버전 불일치일 가능성이 높다. `cargo tree -p wgpu`로
  실제 버전을 확인하고 해당 버전의 docs.rs 문서를 참조할 것.
